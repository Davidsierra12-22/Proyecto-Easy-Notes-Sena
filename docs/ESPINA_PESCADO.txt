DIAGRAMA DE ISHIKAWA (ESPINA DE PESCADO) - CAUSA Y EFECTO
Proyecto: EasyNotes v2 - Sistema de gestión educativa
================================================================

PROBLEMA / EFECTO (cabeza del pescado):
---------------------------------------
"Baja adopción del sistema por parte de los colegios"

DESCRIPCIÓN DEL PROYECTO (contexto para la IA):
-----------------------------------------------
EasyNotes v2 es un sistema web de gestión académica que incluye:
matrículas, calificaciones, recuperaciones/habilitaciones, boletines
en PDF, promoción, contabilidad escolar (pensiones) y comunicación.
- Frontend: React + Vite + Material UI
- Backend: Node.js + Express + MongoDB
- Roles de usuario: Administrador, Docente, Estudiante, Acudiente

----------------------------------------------------------------
1. CATEGORÍA: MÉTODO / PROCESO
----------------------------------------------------------------
- La transición de un proceso manual (libros, planillas) al sistema
  digital resulta incómoda para el personal administrativo.
- El flujo de matrícula es demasiado largo (muchos pasos).
- Las reglas de negocio de recuperaciones y habilitaciones son
  difíciles de entender por los docentes (la recuperación solo
  aplica a notas < 3.0, la habilitación solo a notas de 2.0 a 2.9).
- No existe automatización de recordatorios de pago de pensiones.
- El cierre de período bloquea modificaciones, pero no hay avisos
  de anticipación a los docentes.

----------------------------------------------------------------
2. CATEGORÍA: TECNOLOGÍA
----------------------------------------------------------------
- La aplicación es solo web, no tiene versión móvil.
- Depende de internet y, en su versión local, de una base de datos
  MongoDB instalada en el colegio (no en la nube).
- Posibles bugs en el módulo de cálculo de calificaciones
  (reglas RN-CAL-01 a RN-CAL-05 del documento LOGICA_NEGOCIO.md).
- La generación de reportes PDF usa Puppeteer, lo que consume
  muchos recursos y puede ser lento.
- No hay plantillas de boletines personalizables por el colegio
  (logo, firma del rector) sin intervención de un técnico.

----------------------------------------------------------------
3. CATEGORÍA: PERSONAS
----------------------------------------------------------------
- Docentes con poca competencia digital.
- Rector o directivos resistentes al cambio de sistema.
- Falta de capacitación y de manuales de uso.
- No hay personal de soporte al cliente para resolver dudas.
- La contraseña inicial por defecto (igual al número de documento)
  genera confusión en el primer ingreso.

----------------------------------------------------------------
4. CATEGORÍA: MEDICIÓN
----------------------------------------------------------------
- No hay métricas de uso: no se sabe qué pantallas visitan los
  usuarios ni en qué momento abandonan el sistema.
- No se valida el cálculo de notas contra la normativa del
  Ministerio de Educación.
- No se aprovechan los registros de la bitácora (auditoría) para
  detectar errores.
- No se recopila feedback de usuarios (docentes, acudientes).

----------------------------------------------------------------
5. CATEGORÍA: DATOS / MATERIALES
----------------------------------------------------------------
- Datos de estudiantes duplicados o sin validar.
- La migración de datos del sistema anterior (basado en stored
  procedures) está inconclusa: varias secciones del documento
  LOGICA_NEGOCIO.md están marcadas como "Pendiente".
- No hay herramientas de importación desde Excel/CSV para cargar
  estudiantes, docentes y notas masivamente (solo se está
  valorando con la librería xlsx).
- No existen plantillas estándar para el cargue de datos.

----------------------------------------------------------------
6. CATEGORÍA: ENTORNO
----------------------------------------------------------------
- Colegios con conexión a internet lenta y computadores antiguos.
- Normativa y cambios del Ministerio de Educación que obligan a
  ajustar el sistema constantemente.
- La secretaría o dirección de la institución no aprueba
  presupuesto para licencias ni hardware.
- Competencia con otros sistemas de gestión académica ya
  instalados en los colegios.

----------------------------------------------------------------
CAUSAS RAÍZ PRIORITARIAS (las que se deben atacar primero):
----------------------------------------------------------------
1. Migración de datos inconclusa -> sin los datos del colegio,
   el sistema no se adopta.
2. Falta de métricas de uso -> no se sabe dónde se pierden usuarios.
3. Sin versión móvil -> docentes y acudientes usan el celular.
4. Sin capacitación ni soporte -> el software fracasa aunque sea bueno.
5. Sin importación desde Excel -> el colegio no carga datos
   masivamente y abandona.
